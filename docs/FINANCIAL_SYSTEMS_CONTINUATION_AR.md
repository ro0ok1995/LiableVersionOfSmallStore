# تقرير متابعة ربط الأنظمة المالية — SmallStore

## ما تم تنفيذه في هذه الدفعة

- إضافة `StoreRepository.ensureDefaultFinancialConfiguration()` لإنشاء الحسابات المالية وطرق الدفع القياسية الناقصة فقط، داخل معاملة Room واحدة.
- ربط تهيئة البيانات الأساسية ببداية `MainViewModel` قبل استخدام عمليات الدفع، دون إنشاء عملاء أو موردين أو منتجات أو حركات تجريبية.
- الحساب الافتراضي المعتمد في العمليات القديمة يظل `acc_cash`، وطريقة الدفع النقدي `pm_cash`.
- الحسابات القياسية: `acc_cash`, `acc_bank_palestine`, `acc_palpay`, `acc_jawwalpay`, `acc_maltachat`.
- طرق الدفع المطابقة: `pm_cash`, `pm_bank_palestine`, `pm_palpay`, `pm_jawwalpay`, `pm_maltachat`.
- لا تغييرات على مخطط قاعدة البيانات أو ملفات Migration.

## ملاحظات التدقيق التي تحتاج استكمالًا

- بطاقات «فئات المصروفات»، «الحسابات المالية»، «الرصيد الافتتاحي والإعداد الأولي»، و«رأس المال» في `DataCenterScreen.kt` معلوماتية حاليًا وليست جميعها شاشات إدارة كاملة قابلة للفتح.
- يوجد backend لفئات المصروفات والحسابات المالية والأرصدة الافتتاحية، لكن لا يظهر مسار واجهة مستقل ومتكامل لإدارة الحسابات المالية والأرصدة الافتتاحية من مركز البيانات.
- لا يوجد في النسخة الحالية نظام رأس مال مستقل واضح بكيان وسجل عمليات وتقارير. لا ينبغي تمثيل رأس المال كمصروف أو اختلاقه عبر جدول آخر؛ يلزم تصميم محاسبي واختبار قبل إكمال هذه الوحدة.
- تظل أسماء الحسابات القديمة التي قد تكون مرتبطة بحركات تاريخية دون تعديل. التهيئة تضيف فقط المعرفات القياسية الناقصة ولا تعيد تسمية أو حذف حسابات قائمة.

## التحقق

- تمت مراجعة توقيعات DAO المستخدمة للتأكد من وجود عمليات الإدخال الجماعي وقراءة السجلات.
- تعذّر تشغيل `:app:compileDebugKotlin --offline` لأن Gradle Wrapper حاول تنزيل Gradle 9.3.1 ولم تتوفر شبكة. لذلك لا يُدّعى نجاح البناء أو اختبار التطبيق الفعلي.
